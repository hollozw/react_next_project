# TypeScript 函数 JSDoc 注释生成专家

## 何时使用

在以下任一情况优先应用本技能：

- 用户请求：加注释、写 JSDoc、补文档、生成函数注释、文档化这个函数、Typedoc
- 发现函数（尤其是导出函数 / 公共 API / React hook）缺少 `/** ... */` 或注释信息不足
- code review 中公共方法缺少用途说明、参数含义、返回值语义、异常与示例
- 新增函数后需要补齐可读的 API 文档

## 核心原则（必须遵守）

1. **使用 JSDoc（`/** ... */`）而非普通行注释**，以便 IDE 提示与 Typedoc 生成文档。
2. 所有 **导出的函数、方法、hook** 必须有完整 JSDoc；内部函数至少给简短用途说明，复杂逻辑建议补齐。
3. **类型信息优先从 TypeScript 推断**：不要在 JSDoc 中重复类型（避免 `@param x {string}` 这类冗余）。
4. 描述风格：**简洁、专业、第三人称**；避免“我/我们”，避免口语化夸张。
5. 标签顺序（按需使用，不强制全量）：
   - 一句话概述（首行 summary）
   - 详细说明（可选段落：规则、约束、边界条件）
   - `@param`（每个参数）
   - `@returns`（返回值语义；若 `void` 则省略或说明副作用）
   - `@throws`（明确何时抛、抛什么；能确定类型则写 `{RangeError}` 等）
   - `@example`（至少一个可运行、贴近真实调用的示例）
   - `@see` / `@link`（相关函数/类型）
   - `@since` / `@deprecated`（适用时）
6. React 特殊处理：
   - 自定义 hook：在描述中明确“自定义 Hook”，并在 `@example` 给出调用方式（可包含组件片段）。
   - 事件处理函数：说明触发时机与副作用；不要在 JSDoc 重复事件类型（TS 已推断）。
7. 泛型函数：说明泛型的 **约束、代表含义、对行为的影响**（例如“用于保持输入/输出的类型关联”）。

## 工作流程（执行步骤）

1. **定位目标**：读取用户提供的函数代码或选中片段；若未提供，先让用户贴函数/文件路径/函数名。
2. **分析结构**：
   - 是否导出、是否 async、是否泛型、是否 React hook、是否工具函数/公共 API
   - 参数：名称、是否可选、默认值、是否 rest、是否对象参数（destructuring）
   - 返回：返回值语义（Promise/联合类型/Result 模式/void），以及副作用（I/O、状态更新、缓存等）
   - 异常：显式 `throw`、可能冒泡的错误、输入校验失败路径
3. **补齐缺口**（信息不足时优先提 2–4 个问题）：
   - 这个函数的业务意图/用途是什么？
   - 关键边界条件是什么（空值、越界、权限、网络失败等）？
   - 是否需要稳定的示例（含典型输入与期望输出）？
   - 是否有需要强调的副作用或性能约束？
4. **生成并插入 JSDoc**：放在函数声明正上方，紧贴 `function` / `const foo = (...) =>` / `export ...`。
5. **输出呈现**：
   - 先给“修改前”的简短签名（1–2 行）
   - 再给“带完整 JSDoc”的版本
   - 最后询问是否需要批量补齐其它函数、或调整语气/详略/示例数量

## 输出模板（优先使用）

### 通用模板（函数 / 方法）

使用该骨架并按需删减：

```ts
/**
 * [一句话概述：动词开头，说明用途与结果]
 *
 * [可选：补充规则/约束/边界条件/副作用]
 *
 * @param arg - [参数语义，而非类型]
 * @returns [返回值语义与含义；Promise 说明 resolve 的内容]
 * @throws {ErrorType} [触发条件]
 * @example
 * ```ts
 * // [可运行示例，贴近真实调用]
 * ```
 */
```

### 泛型函数（强调类型关联）

- 说明泛型代表什么
- 说明约束（如 `T extends ...`）与行为关系
- 若返回值与输入保持关联，点明“类型保持/映射”

### async / Promise 返回

- `@returns` 描述 **resolve 值**（不要写类型）
- 若会 reject/throw，使用 `@throws` 描述触发条件（可提及网络/解析失败等）

### React 自定义 Hook

- 描述中明确“自定义 Hook”，说明状态来源、返回结构、订阅/清理、副作用
- `@example` 提供最小可用的组件片段
